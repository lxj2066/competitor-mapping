# competitor-mapping-agent

> 版本：1.0.0

给一个目标公司或一个技术方向，交一份每条判断都能回溯到证据行的竞对映射档案。不交「感觉像对标」的名单。

## 它解决什么

对标映射最常见的两种翻车：**假阳性**（把长得像的当对手，战略照着错的定位走）和**假阴性**（漏掉真对手，还自以为看全了）。前者靠强制反证控制，后者靠多路召回与留一法回测控制。这两件事都不是靠更强的模型能解决的，只能靠流程与判据。

## 工作流（S0 至 S7）

1. **S0 冻结口径**：直接、间接、潜在、可比四类，配时间窗、地域与规模带。不冻结不出分。
2. **S1 解析目标**：技术、产品、产业链位、市场四维，每维至少一条可验证锚点。
3. **S2 五路召回**：产业链、专利异构图、专利语义分布、产品市场、图扩散，各留证据与独立来源标识。
4. **S3 确定性质量门**：G1 经营状态、G2 来源独立性、G3 时效、G4 主体同一性、G5 口径对齐、G6 规模、G7 核验时效。纯规则，把单源幻觉召回挡在打分前。
5. **S4 校准融合**：对数几率池化加通道一致性加成与冲突惩罚，给分数、区间与通道贡献分解。权重由标注对拟合，不拍脑袋。
6. **S5 强制反证**：技术路线互斥、客群不重叠、商业模式不同、地域隔离、规模阶段错配。反证是否决项，缺字段记 unverified。
7. **S6 分层档案**：T1 深度（五大量化加三条结构性判断）、T2 定位卡、T3 观察。
8. **S7 增量监控**：专利主题漂移、招聘技术栈漂移、产品与定价结构变更、融资并购、专利增速。只按信号触发，不做定时全量。

## 交付物

`dossier.md` 与自包含 `dossier.html` 是主交付；同时给 `fused.json`（分数、区间、贡献）、`critique.json`（反证清单与状态）、`monitor.json`（监控注册）、`eval-report.json`（指标与留一法回测）。

## 装法与用法

1. 把这个目录放进 WorkBuddy 的自建专家库，或在市场里安装本专家包。
2. 打开对话，直接说「帮我把这家公司的竞争对手映射出来」，并给出目标名与该赛道的技术术语。
3. 需要复现脚本结果时，技能目录内有六个纯标准库脚本，按 SKILL.md 的调用顺序执行即可。

## 边界

- 不构成投资建议，不给估值口径，不给买卖结论。
- 所有数字必须现场取数并标注日期与出处，检索失败写检索失败。
- 数据源凭证不进包，一律用占位符由运行环境注入。
