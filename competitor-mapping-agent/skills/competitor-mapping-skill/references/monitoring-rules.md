# 监控与增量重评规则

> 映射不是一次性交付物。变化发生时才重评，不做定时全量。
> 实现脚本：`scripts/drift.py`。规则阈值写在 `monitor.json`，每个对标单独可调。

## 1 五类漂移信号

| 码 | 信号 | 计算口径 | 默认阈值 | 重评范围 |
|---|---|---|---|---|
| `D1` | 专利主题漂移 | 基线期与当期主题分布的 JS 散度（以 2 为底，取值 0 至 1） | `js > 0.15` | 技术定位与 T1 专利向、专利质两项 |
| `D2` | 招聘技术栈漂移 | 期内岗位技术关键词 top20 集合的 Jaccard 相似度 | `jaccard < 0.60` | 观察名单升为 T2 候选，不做分数重算 |
| `D3` | 产品与定价结构变更 | 产品页结构指纹变化，或定价带中位变动幅度 | `hash 不同` 或 `变动 >20%` | 产品重叠度与功能矩阵重算 |
| `D4` | 融资并购事件 | 期内新增融资轮次或收购方、被收购方关系变化 | `存在新事件` | 全量重审：分类口径、产业链位、分层 |
| `D5` | 专利增速异常 | 当期新增数与近三年年均新增数之比 | `ratio > 2.0` 或 `< 0.3` | 技术定位重评，必要时升 T2 |

`D4` 是唯一触发全量的码。并购会改变主体边界，主体一变，前面所有按主体聚合的指标都失效，此时局部重算会自欺。

## 2 触发后的动作清单

每个触发都必须产出四样，缺一视为未处理：

1. 触发快照：指标值、阈值、计算区间、数据出处。
2. 受影响结论：上一版档案中哪几条判断失效，逐条列出。
3. 重评结果：新分数与旧分数并排，说明差异来源（哪个通道贡献变了）。
4. 结论变更记录：写进 `dossier` 的变更段，保留上一版文件。

## 3 阈值怎么定

阈值不是拍出来的，按信号的自然波动定：

- 对同一主体取过去 6 至 8 个观测点，算指标分布的 90 分位，阈值取该分位略上方。
- 观测点不足 4 个时，用本册默认值，并在 `monitor.json` 中标记 `threshold_source: "default"`，表示阈值未经本地化。
- 阈值一年至少复核一次，行业进入技术换代期时缩短到季度。

## 4 成本纪律

| 做法 | 是否允许 | 原因 |
|---|---|---|
| 每个对标每周全量重跑 | 否 | 成本高且掩盖真实信号，噪声进档案 |
| 只跑触发命中的标的与通道 | 是 | 与信号强度匹配 |
| 触发后只更新分数不更新反证 | 否 | 分数变了反证结论可能失效，必须同批复核 |
| 一次事件触发全部对标全量 | 否，`D4` 除外 | 单主体并购不影响其他主体 |

## 5 监控注册表结构

```json
{
  "target": "示例目标公司",
  "registered_at": "2026-10-26",
  "entities": [
    {
      "id": "c001",
      "name": "示例对标",
      "tier": "T1",
      "baseline": {"patent_topics": {"rv": 0.42, "harmonic": 0.18},
                   "hiring_keywords": ["cuda", "reinforcement-learning"],
                   "pricing_page_hash": "8f14e45f",
                   "patent_count": 128,
                   "last_funding_event": "2024-06-11"},
      "rules": ["D1", "D3", "D4"],
      "threshold_source": "default"
    }
  ]
}
```

`rules` 至少两条：只挂一条的监控等于没监控，单一信号极易假阳性。

## 6 与评估的接口

每次重评后把人工确认与排除的操作回流为标注对，累计 12 对触发一次权重校准（见 `mapping-methodology.md` 第 6 节）。校准前后的权重与分数一并存档，回答「这次的分数为什么和上季度不一样」。
