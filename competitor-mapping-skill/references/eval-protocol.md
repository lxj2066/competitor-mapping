# 评估与校准协议

> 没有评估就不知道「找得对不对、漏没漏」。本册定指标、标注口径与回测流程。
> 实现脚本：`scripts/eval.py`。

## 1 标注口径（先定尺子）

每个目标公司配一份判定集，对候选给三档相关度：

| 档 | 含义 | 对应分类 |
|---|---|---|
| `2` | 核心对标，可作定位参照 | `direct` |
| `1` | 次要对标，需注明不可比维度 | `indirect`、`potential` |
| `0` | 无关或仅可比 | `comparable`、误召 |

两条纪律：

1. 标注必须写理由类别（技术、客户、模式、产业链），否则无法分析哪个通道在拖后腿。
2. 同一标注集版本冻结，改口径就升版本号，旧指标不覆写。

## 2 三项指标

```
rel 取 0/1/2；K 默认 10
P@K     = |{i ≤ K : rel_i ≥ 1}| / K
R@K     = |{i ≤ K : rel_i ≥ 1}| / |{标注集中 rel ≥ 1 的总数}|
DCG@K   = Σ_{i=1..K} (2^rel_i - 1) / log2(i + 1)
NDCG@K  = DCG@K / IDCG@K      （IDCG 为理想排序的 DCG）
```

三项各看什么：

- `P@K` 看前 K 里有多少是垃圾，直接决定人工复核成本。
- `R@K` 看漏没漏，漏掉一个直接对标比多列三个无关项更贵。
- `NDCG@K` 看排序质量，是否把 `direct` 排在 `indirect` 前面。

多目标时取宏平均，并单列最差的那个目标。平均分好看但某目标全错，等于没评估。

## 3 冷启动：种子对标对

- 规模：20 至 30 个已知关系对，四类口径都要有。
- 用途一：校准通道权重，最少 12 对才够拟合。
- 用途二：作为图扩散的种子，种子选偏会让整片召回偏，所以要覆盖不同类型而非同类堆叠。
- 用途三：作为回测的留出池。

## 4 留一法回测（比静态指标更接近实战）

流程：

1. 从标注集中取一个已知对标 `x`，从种子清单与图输入中移除 `x` 及其直接边。
2. 重跑召回与排序，得到不含 `x` 先验的结果。
3. 检查 `x` 是否出现在前 K 名内。

```
LOO-Recall@K = 命中的留出项数 / 留出的总项数
```

为什么必须做：静态指标测的是「给定候选能不能排对」，留一法测的是「没有先验时能不能自己找到」。后者才反映召回路径的真实能力。

判定基准（经验值，非承诺）：

| LOO-Recall@10 | 含义 | 动作 |
|---|---|---|
| ≥ 0.70 | 召回路径可用 | 进入常规增量监控 |
| 0.40 至 0.69 | 依赖种子过度 | 检查 `graph_diffusion` 权重是否过高 |
| < 0.40 | 召回路径失效 | 回 S2 重做通道设计，不许靠调阈值掩盖 |

## 5 评估节奏

| 时点 | 做什么 | 产出 |
|---|---|---|
| 冷启动 | 建标注集、校准权重、跑一次留一法 | `eval-report.json` 首版 |
| 每次增量重评后 | 对 Top-K 做留一法抽检，抽样 3 个留出项 | 追加指标行 |
| 每季度 | 全量重跑三项指标，与上季对比 | 指标趋势与差异归因 |
| 口径变更时 | 升标注版本，重跑全部指标 | 新旧版本并列，不混算 |

## 6 指标异常怎么读

| 现象 | 最可能的原因 | 先查什么 |
|---|---|---|
| P@10 高但 LOO 低 | 排序好、召回路窄 | 种子覆盖与图通道权重 |
| R@10 高但 NDCG 低 | 找得全、排得乱 | 融合权重与冲突惩罚是否失效 |
| 各目标方差大 | 某类口径的通道缺数据 | 按分类分组看指标，找短板通道 |
| 指标突降 | 数据源口径变了 | 先查 `source-adapters.md` 的字段是否仍可用 |

指标变好但人工复核否决率上升，说明标注集与真实判断脱节，先修标注，不许先调权重。

## 7 不许做的事

- 不许为了让指标好看而改标注口径（改口径必须升版本并写明）。
- 不许只在表现好的目标上汇报指标。
- 不许把缺失数据的通道按 0 分参与评估，缺失必须显式排除并记录。
- 不许用一次评估结论推断长期能力，样本少于 10 个目标时只报区间不报点值。
